Explicit rules. No automatic CRM writes.

  1. Discover completely. Crawl homepage, directory pagination and linked details. Deduplicate by canonical URL and normalized address. Stop the run on fetch failures, parsing failures, or a shortfall against the homepage count.
  2. Match the address first. Normalize punctuation, directions and street suffixes; require locality and ZIP. An exact name plus street/locality can support a ZIP correction. Name alone never overrides conflicting streets.
  3. Preserve billing history. A parent change with positive revenue and positive AR creates a successor and links the old account. The old account's other fields stay unchanged. Zero revenue OR zero AR allows direct re-parenting.
  4. Mark duplicate copies. Prefer billing history, existing Bellhaven ownership, active status, then stable ID. Only zero-balance losing copies are eligible. Set Inactive and duplicate_of_account; never delete or merge. Correct the survivor first.
  5. Flag uncertainty. A missing website listing is not proof of a sale. Apply Needs Review and explanatory notes while keeping the parent and financial fields intact.
  6. Approve deliberately. Each approval re-crawls the website, re-fetches the CRM, compares the deterministic proposal, and rechecks financial safety. Writes are journaled before sending and verified by read-back.
  7. Stop on uncertainty after a write. A timeout or partial CHOW enters recovery_required. No automatic POST retry. Inspect the durable operation journal and follow the recovery runbook.

Confidence scores are deterministic evidence tiers, not statistically calibrated probabilities. This local prototype trusts the named reviewer; it has no identity provider.
